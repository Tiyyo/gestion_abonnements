# Sluis (app de gestion d'abonnements)

**Sluis** (« écluse » en néerlandais) : application mobile personnelle (un seul utilisateur, Android) qui suit les abonnements, calcule le plan d'alimentation Revolut et protège contre les essais gratuits oubliés. Langue du produit et des commentaires métier : français.

## Principe métier (à ne jamais casser)

- Le compte Revolut reste à 0 € ; l'argent dort dans un coffre.
- Chaque prélèvement **voulu** est financé juste avant sa date (J-1, ou dernier jour ouvré précédent) : coffre → compte principal, montant + marge.
- Un prélèvement **non voulu** (essai oublié, abonnement à résilier) n'est jamais financé (`charge.status = 'unfunded'`) : il échoue faute de solde.
- Marge en pourcentage, plafonnée à 5 %.

## Où la conception a évolué (le code et la fiche de stack priment)

- Marges stockées en **points de base** (`*_margin_bp`, 300 = 3 %, plafond 500), pas en pourcentage décimal.
- **Pas de trigger de cascade** à la résiliation : cette logique est dans `packages/core` (elle replanifie aussi les notifications). Seuls les triggers `updated_at` restent en base.
- Pas de table `schema_migrations` : Kysely gère la sienne.
- La vue `v_upcoming_charge` n'a pas de filtre sur la date du jour : le repository passe la date (fuseau Europe/Paris).
- Backend IA en **Go** (Scaleway Serverless Functions), pas en TypeScript ; contrat de référence en JSON Schema.
- **Décisions v1** (`modele-de-donnees.md` section 9) : euro uniquement, solde estimé unique, alerte d'essai sans modifier le plan, virement de paie reporté au jour ouvré suivant, rattachement par date de transfert, provision avec marge et complément, question à J+1 sans décision sur un essai, régénération sur place. Elles priment sur les sections 3 et 5.
- **Compléments v1** (section 10) : report de transfert via `transfer.rescheduled_date` (migration `002` à écrire), question J+1 en fin de période à résilier, rapprochement complet, logos Simple Icons avec repli initiales, contrat `contracts/enrich.schema.json`, import en remplacement seul, écrans complémentaires. Ils priment sur les sections 2, 3.8, 4, 6 et 7.

Expo SDK 58 (React Native 0.88, React 19.3, New Architecture), Expo Router (routes dans `apps/mobile/src/app/`), Tamagui 3.3, Reanimated 4.7 + `react-native-worklets`, `expo-sqlite` + Kysely 0.29, TanStack Query 5, React Hook Form + Zod, notifications locales `expo-notifications`. Tests : Vitest 5 + `better-sqlite3`. Monorepo pnpm (`node-linker=hoisted`).

## CI

GitHub Actions, `.github/workflows/ci.yml`, sur chaque pull request et chaque push sur `main` (exécution précédente annulée, permission `contents: read`, aucun secret, pas de build APK ni de déploiement). Trois jobs : **mobile** (`tsc --noEmit`, `eslint . --max-warnings 0`, `vitest run`, `expo-doctor`, `expo export --platform android` pour le bundle Hermes, sans `.env.local`), **core** (types et tests de `packages/core`), **enrich** (`go vet`, `go test`, puis `go test ./... -update` qui doit laisser `contracts/` inchangé). Node figé dans `.nvmrc`, pnpm dans `packageManager`, Go dans `apps/enrich/go.mod`. Mêmes contrôles en local depuis la racine : `pnpm check` (= `pnpm typecheck && pnpm lint && pnpm test`), `pnpm bundle` (bundle Hermes), `pnpm test:enrich` (Go). `pnpm-lock.yaml` est mis en forme par Prettier (`npx prettier --no-config --write pnpm-lock.yaml` après une installation, pour garder un diff lisible). Une dépendance importée par le bundle doit être déclarée dans `apps/mobile/package.json` : une installation propre (`--frozen-lockfile`) ne matérialise pas les pairs installés automatiquement (cas de `@expo/metro-runtime`, requis par `expo-router`).

## Pièges connus (spike du 19/11/2026)

- **Dialecte Kysely maison** : `src/db/expo-sqlite-database.ts` adapte l'API synchrone d'`expo-sqlite` au `SqliteDialect` intégré à Kysely. Aucun dialecte communautaire n'était à jour pour le SDK 58.
- **`kysely/migration` et Hermes** : l'entrée embarque `FileMigrationProvider` (`import()` dynamique, refusé par Hermes). `metro.config.js` redirige `kysely/migration` vers `migrator.js`. Ne pas retirer cette redirection.
- **Tamagui 3** : valeurs de thème et de tokens **sans `$`** (`bg="primary"`, `gap="4"`) ; config v6 = **raccourcis obligatoires** (`p`, `px`, `pt`, `items`, `justify`, `rounded`, `minH`…) ; `animation` → `transition`, `enterStyle` / `pressStyle` → modificateurs dans la valeur (`opacity="1 enter:0"`, `bg="primary press:…"`). Rayons : `rounded="xl"`. Icônes : `lucide-react-native`.
- **Jamais de `lineHeight` numérique ni d'`adjustsFontSizeToFit`** sur un texte Tamagui : sous Android, le texte s'étire sur toute la hauteur et écrase le reste de l'écran (constaté le 19/11/2026).
- **`Modal` + `statusBarTranslucent`** : sous Android, la fenêtre de la modale s'agrandit de la hauteur de la barre d'état juste après l'ouverture, et tout contenu collé en bas saute de ~29 dp. Ne pas l'utiliser pour la feuille du bas (`ui/feedback/show-dialog.ts`, hôte `dialog-host.tsx`) ; garder `navigationBarTranslucent` avec un `SafeAreaProvider` dans la modale, et figer la marge du bas sur la plus grande valeur reçue (elle passe brièvement à 0).
- Pas de plugin Babel Tamagui (compilateur désactivé, cf. stack.md 4.1).

## Architecture du code (`apps/mobile/src`, refonte du 20/11/2026)

- Organisation **par feature** : `app/` (routes Expo Router **minces** : paramètres de route + hooks + assemblage de composants, aucune logique), `features/<feature>/` (`components/`, `hooks/`, logique pure en `.ts` testée à côté, `*.test.ts`), `ui/` (design system sans métier : `text/`, `surfaces/`, `controls/`, `navigation/` dont `tab-bar/`, `feedback/`, `motion/`, `brand/`, `hooks/`), `theme/` (couleurs, `elevation`, `layout`, config Tamagui), `lib/` (utilitaires purs), `config/`, `db/` (client, migrations, `repositories/`, `commands/`, `reconcile/`, `sync/`), `notifications/`.
- Features : `app-shell`, `home`, `plan`, `charges` (rapprochement, prélèvement inconnu), `subscriptions`, `settings`, `security`, `backup`, `balances`, `bank-sync` (rapprochement automatique), `consent` (renouvellement de l'accord bancaire), `enrich`, `stats`, `widget` (instantané du widget Android).
- Règles (vérifiées par ESLint) : fichiers et dossiers en **kebab-case** (sauf `_layout`, `[id]`, `(tabs)`, migrations `NNN-nom`) ; un fichier = une responsabilité (un composant ou un hook exporté par fichier) ; ≤ 200 lignes par fichier, ≤ 80 lignes par fonction ; imports par l'alias `@/` (→ `src/`), `./` pour un voisin, jamais `../` ; pas de fichier barrel. Les calculs (libellés, dates, montants, regroupements) sont des fonctions pures testées, hors des composants. Seuls `db/repositories`, `db/commands`, `db/reconcile` et `db/sync` utilisent Kysely.
- **Statistiques** (20/11/2026) : tendance sur 12 mois calendaires (`db/repositories/stats-trend.ts` : payé = mêmes prélèvements que « Dépensé sur 12 mois », rangés par mois de `actual_date` ; prévu = `planned`/`funded` du mois en cours et du suivant, hors `unfunded`, provisions et abonnements archivés). Graphique maison en `react-native-svg` (`features/stats/components/trend-*.tsx`, aucune bibliothèque de graphiques) ; échelle et tracés dans `trend-scale.ts`, libellés dans `trend-format.ts`, enseignements dans `trend-insights.ts` (tous testés). Colonnes tactiles de 44 px : le graphique défile horizontalement, calé sur le mois en cours.

## Conventions

- Montants en **centimes** (entiers), jamais de flottants. Arrondi au centime supérieur : `(montant × (10000 + marge_bp) + 9999) / 10000`.
- Dates en `YYYY-MM-DD`, fuseau Europe/Paris ; horodatages en ISO 8601 UTC.
- Identifiants UUID v4 générés côté app. Suppression logique via `archived_at`.
- `packages/core` est du TypeScript **pur** : aucune dépendance à React Native, Expo ni à la base.
- Toute règle métier vit dans `core` et est testée ; les repositories sont les seuls à parler à Kysely ; les écrans passent par des hooks TanStack Query.
- Pas de commentaires SQL isolés dans les migrations (ancien bug de migrations Expo SQLite sur Android).
- **Interface** : passer par le design system `src/ui` (échelle typographique dans `ui/text/typography.tsx` : `Overline`, `ScreenTitle`, `Heading`, `CardTitle`, `Body`, `Label`, `Caption`, `Amount`/`Display` en chiffres tabulaires ; `Card`, `ListCard`, `ActionButton`, `IconButton`, `ScreenHeader`, `StackHeader`, `SheetHeader`, `KeyValue`, `PickerRow` ; marge sous la barre d'état `pt={insets.top + TOP_GAP.tab}` (32) pour les onglets, `TOP_GAP.stack` (20) pour les autres écrans). Pas de `fontSize` ni de bouton maison dans les écrans. Icônes lucide uniquement, jamais de glyphes texte (‹ › + ✓). Montants avec `formatEuros`, pourcentages avec `formatPercentBp` (espace insécable avant € et %). Un seul bouton plein par vue ; danger réservé aux actions destructrices. Fenêtres de confirmation et messages : `showDialog` / `showError` (`ui/feedback/show-dialog.ts`, hôte `dialog-host.tsx`, même signature qu'`Alert.alert`, option `tone` et `cancelable`), jamais `Alert.alert`. **Annuler plutôt que confirmer** : une action fréquente qu'une commande existante défait exactement (marquer un transfert fait, reporter, virement de paie fait, arrêter un abonnement) est faite tout de suite puis annoncée par `showToast(message, { action })` (`ui/feedback/show-toast.ts`, hôte `toast-host.tsx` monté dans `AppShell`, un message à la fois, 5 s ou 8 s avec action, au-dessus de la barre d'onglets) dont le bouton « Annuler » lance la commande inverse (`features/plan/plan-feedback.ts` + `hooks/use-plan-run.ts`) ; les allers-retours sont vérifiés dans `db/undo-round-trips.test.ts`. `showDialog` reste réservé aux actions irréversibles ou sans inverse exact (prélèvement passé ou échoué, résiliation, suppression, retour au coffre, annulation d'un virement de paie, remise « à faire »). Choix dans une liste : ligne « libellé → valeur › » qui ouvre un `BottomSheet` avec des `SheetOption` (`ui/feedback/bottom-sheet.tsx` et `sheet-option.tsx`, le même panneau que les dialogues) ; choix binaire : `Segmented` (`ui/controls/segmented.tsx`). Mouvement : `ui/motion/` (`haptics`, `easing`, `appear`, `reveal`, `settle`) (courbes courtes sans rebond, décalages de 6 à 10 px ; `haptic.select/tap/success/warn/error`, `Appear` pour les éléments de liste avec cascade et sortie, `Reveal` pour un contenu dépliable, `Settle` pour que les voisins glissent) ; retour de pression discret via `scale="1 press:0.985" transition="fast"` (déjà dans le kit). **Jamais de ressort** : les préréglages Tamagui (`quick`, `bouncy`, même `…LessBouncy`) et `withSpring`/`springify` rebondissent ; utiliser `transition="fast"` (120 ms) ou `"smooth"` (200 ms), définis en `timing` dans `tamagui.config.ts`, et `withTiming`/`.duration().easing()` côté Reanimated ; transitions de pile `ios_from_right`, formulaires en feuille du bas sans geste de fermeture (option de route `SHEET`, `gestureEnabled: false`, pour ne pas perdre une saisie), onglets `shift`. Mise en forme : `npm run format` (Prettier, `.prettierrc.json`).
- **Dates affichées** : uniquement via `src/lib/dates.ts` (tables françaises écrites à la main, lecture UTC par `core` : jamais de `toLocaleDateString`, d'`Intl.DateTimeFormat` ni de `new Date('YYYY-MM-DD')` pour afficher, jamais de `slice` sur une date dans un écran). Formats : `dateShort` « 27 nov. » (listes, légendes, phrases, dialogues, notifications ; passer `today` là où la date peut tomber une autre année, champs de formulaire et historique : « 5 janv. 2027 ») ; `dateShortYear` « 17 mai 2027 » (dates durables : accord bancaire, fichier de sauvegarde) ; `dateWithWeekday` « ven. 27 nov. » (transferts, échéances de la fiche) ; `dateLong` « vendredi 27 novembre » (surtitre du jour, libellés d'accessibilité) ; `monthYearTitle` « Novembre 2026 » ; `monthTile` « nov » (vignette calendrier seulement) ; `relativeDay` « aujourd’hui », « demain », « dans 3 jours ». Pas de date numérique `jj/mm/aaaa` à l'écran. Règles : minuscules (`capitalize` seulement en tête de ligne), mois abrégés avec point sauf mars, mai, juin, août, « 1er », espaces insécables dans la date (`\u00a0` dans les tests). Horodatage ISO → jour de Paris avec `dateOfTimestamp`, pas `slice(0, 10)`.
- **Saisie jamais perdue** (20/11/2026) : tout écran de saisie appelle `useDiscardGuard(dirty, message)` (`ui/navigation/use-discard-guard.ts`). Tant que `dirty` est vrai, quitter l'écran (retour Android, « Annuler », `router.back()`, `router.replace()`) ouvre « Abandonner la saisie ? » ; rien n'est demandé sur un formulaire intact. `dirty` vient d'une fonction pure testée qui compare aux valeurs de départ (`isSubscriptionFormDirty`, `isUnknownDebitDirty`, `isReviewDirty`), pas de `formState.isDirty` (il ignore les `setValue`). Après un enregistrement réussi, fermer par `guard.leave()` (ou `guard.release()` avant un `router.replace`), jamais par `router.back()` direct, sinon la question est posée sur une saisie déjà enregistrée. La garde repose sur `usePreventRemove` d'expo-router : l'évènement `beforeRemove` de React Navigation n'existe plus dans la navigation embarquée du SDK 58.
- **Profondeur et verre** (20/11/2026) : ombres uniquement via `src/theme/elevation.ts` (`shadow.sm/md/lg/glow/…`, `RADIUS.card/row/control/glass`), jamais de `boxShadow` écrit à la main. Écrans d'onglet et Statistiques : en-tête `Hero` (`ui/surfaces/hero.tsx`, dégradé aubergine en `backgroundImage` natif) + `ScreenHeader onHero` / `StackHeader onHero`, barre d'état claire tant que l'écran a le focus. Sur le dégradé : `GlassCard` / `GlassPanel` (`ui/surfaces/glass-card.tsx`, `glass-panel.tsx`, verre sombre teinté, sans flou), `HeroAmount`, `IconButton variant="glass"`, `Segmented onGlass`, couleurs `onGlass*` (contrastes mesurés). Formulaires (abonnement, prélèvement non prévu, rapprochement) en feuille du bas (`ui/surfaces/sheet-screen.tsx`, route `transparentModal`, ni poignée ni fermeture par glissement ; `SheetFooter` accepte une seconde réponse `secondary` en contour). Fiche d'abonnement : `Hero` + carte en verre (`GlassKeyValue` pour les échéances), cartes qui remontent de `HERO_OVERLAP` (`theme/layout.ts`). Premier lancement et verrouillage : `Hero` plein écran, marque immobile `BrandMark` (`ui/brand/brand-mark.tsx`). Sur le dégradé, le bouton plein est `variant="secondary"` (pêche, `primary` s'y confond), les autres `glass` ou `glassGhost` ; contrôles de réglage réutilisés sur verre via leur prop `onGlass` (`PaydayGrid`, `MarginStepper`, `StatusBadge`). Barre d'onglets flottante unique (`ui/navigation/tab-bar/`, capsule « iris », flou Dimezis réglable par `ANDROID_BLUR`). Titres et grands montants en Space Grotesk (`DISPLAY_FONT`, sans `fontWeight`). Après un changement qui ne se voit pas dans Expo Go : `npx expo start --go --clear`.
- **États de chargement** (20/11/2026) : pas de `Spinner` nu pour un écran ou une carte : il est réservé aux boutons occupés (`ActionButton loading`) et au démarrage (Réglages, Modifier et la feuille Rapprochement l'utilisent encore, à convertir). Écran fantôme à la forme du contenu : `Skeleton` (`ui/feedback/skeleton.tsx`, bloc à pulsation d'opacité de 1,2 s, fixe si les animations sont réduites, tons `light` = `subtle` et `glass` = `glassSkeleton`) et `SkeletonLine` (`skeleton-line.tsx` : on lui passe le composant typographique du contenu final, rendu invisible, pour obtenir exactement la même hauteur de ligne, donc aucun saut de mise en page) dans un `SkeletonGroup` (un seul élément annoncé « Chargement… », `busy` ; `BUSY_A11Y` pour un conteneur existant). Un composant `*-skeleton.tsx` par écran dans `features/<feature>/components/`. Requêtes locales : n'afficher le fantôme qu'après 150 ms (`useDelayedFlag`, `ui/hooks/`), rien avant. Soldes Revolut : fantômes seulement sans aucune valeur à l'écran ; une actualisation garde les valeurs et la pastille « Actualisation… » ; le tiret « — » signifie « pas de donnée » (erreur, accord expiré).

## Build Android local

- APK release : `cd apps/mobile/android && ./gradlew assembleRelease` (sortie dans `app/build/outputs/apk/release/`). Premier build environ 16 min.
- Development build (`expo-dev-client`) : `./gradlew assembleDebug`, puis `npx expo start` dans `apps/mobile` et `adb reverse tcp:8081 tcp:8081`.
- MIUI refuse souvent `adb install` (`INSTALL_FAILED_USER_RESTRICTED`, fenêtre de confirmation qui expire) : copier l'APK avec `adb push <apk> /sdcard/Download/` et l'installer depuis le gestionnaire de fichiers.
